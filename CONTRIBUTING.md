# Contributing to sshelfy

Thanks for your interest! Bug reports, ideas and pull requests are all welcome.

## Before you start

- **Bugs and ideas:** open an issue first (templates are provided). For anything larger than a small
  fix, please discuss the approach in an issue before writing a lot of code.
- **Security problems:** do not open a public issue; see [SECURITY.md](SECURITY.md).
- **Code of conduct:** everyone taking part is expected to follow the
  [Code of Conduct](CODE_OF_CONDUCT.md).

## Building

Requirements: Windows 10/11 and the .NET 10 SDK (10.0.102 or newer).

```
dotnet build
dotnet run --project src/Sshelfy.App
```

Use `SSHELFY_DATA_DIR` to run with a separate data folder, so development does not touch your own
hosts and vault:

```
set SSHELFY_DATA_DIR=%TEMP%\sshelfy-dev
dotnet run --project src/Sshelfy.App
```

## Tests

```
dotnet test
```

Unit tests and the headless UI tests need no setup. The SSH/SFTP integration tests run against a
local OpenSSH container; the README section **Tests** has the exact `docker` commands and the
`SSHELFY_TEST_*` variables. Please run them for changes that touch SSH, SFTP, tunnels or keys.

## How the code is organised

The README describes the projects. A few rules keep the code base consistent:

- **Logic belongs in `Sshelfy.Core`** (no UI and no SSH.NET dependency), implementations of
  its abstractions in `Sshelfy.Infrastructure`, views and view models in `Sshelfy.App`.
- **MVVM without code-behind logic:** view-only behaviour (focus, drag and drop, double tap) goes
  through attached behaviors in `App/Behaviors`; views are mapped to view models in `App.axaml`.
- **Design tokens only:** colours, spacing, radii and icons come from `src/Sshelfy.App/Themes`
  (icons are Lucide, generated by `tools/gen_icons.py`). Do not hard-code colours in views.
- **Secrets only in the vault** (`ISecretVault`), never in JSON files, logs or temp files.
- Code, UI text and commit messages are in English. Write comments that explain *why*, not *what*.

## Pull requests

- Keep a pull request to one topic, with tests for new behaviour and bug fixes.
- Make sure `dotnet build` has no warnings and `dotnet test` passes.
- Describe what changed and how you checked it (for UI changes, a screenshot helps).
- By contributing you agree that your contribution is licensed under the MIT License.

## Releases (maintainers)

1. Move the `Unreleased` notes in `CHANGELOG.md` under a new version heading, e.g. `## [1.1.0] - 2026-12-01`.
2. Commit, then tag and push: `git tag v1.1.0 && git push origin v1.1.0`.
3. The **Release** workflow runs the tests, builds the self-contained `sshelfy.exe` with that version,
   and publishes a GitHub release with the exe, a ZIP, SHA-256 checksums and the changelog section as notes.
   Installed copies see the new version through the update check within a day.
